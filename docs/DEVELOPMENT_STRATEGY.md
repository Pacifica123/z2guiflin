# Стратегия разработки текущего кандидата

GUI использует PyQt6. Семантическую власть сохраняют канонические ActionContract и dispatcher; поиск, help, установочная оболочка и документация являются проекциями существующих контрактов. P06 не меняет сетевые verdict и не добавляет автоматическое включение сервисов.

## Правило языка документации

Активная проектная документация ведётся на русском языке. Все будущие изменения должны обновлять текущие пользовательские и эксплуатационные инструкции вместе с кодом. Исторические оригиналы сохраняются побайтно и снабжаются явным контекстом этапа; их временные утверждения не переносятся в текущий статус.

Порядок разработки: проверка входного snapshot, изменения с ограниченным владением, генерация справочника, единый профиль приёмки, затем clean VM receipt и review. Проверка package staging не подменяет системную установку. Service unit остаётся plan-only до самостоятельного полного lifecycle.

Текущий этап P07: compositional qualification кандидата 1.0.0rc7. До независимого review всех MUST partitions финальная версия не присваивается. Qualification не вводит новую runtime архитектуру; выявленные локальные дефекты возвращаются владельцу области и фиксируются в явном SA.
