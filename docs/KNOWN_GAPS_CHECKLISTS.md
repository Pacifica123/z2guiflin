# Чеклисты недостатков z2guiflin

## Назначение

Этот файл собирает текущий технический и продуктовый долг в одном месте. Категоризация горизонтальная: каждый раздел описывает одну область продукта и сравнивает z2guiflin сразу с несколькими ориентирами, а не создаёт отдельный список для каждого внешнего проекта.

Ориентиры аудита:

- upstream `zapret2` от bol-van — ядро, `blockcheck2`, профили, Linux interception и service scripts;
- Windows GUI от loop-uh — управление пресетами, live orchestrator, DNS, updater, autostart, tray и process lifecycle;
- Flowseal — готовые наборы стратегий, service workflow, hostlist/ipset и понятный массовый пользовательский сценарий;
- текущий код z2guiflin из снимка `v0.4-alpha_stage8f-r3`.

Обозначения:

- `[x]` — реализовано и входит в v0.4;
- `[~]` — реализовано частично, экспериментально или без законченного пользовательского контура;
- `[ ]` — отсутствует или не доведено до рабочего состояния.

## 1. Установка, зависимости и обновление

- [x] Есть локальный launcher `./run.sh` без скрытого `sudo`.
- [x] Есть inventory/build map и plan локальной сборки vendored `zapret2`.
- [~] Есть dependency preflight, но исправление зависимостей остаётся ручным.
- [ ] Нет `PKGBUILD`/AUR-пакета и проверяемой установки как системного приложения Arch.
- [ ] Нет `.desktop` файла, иконки установки и стандартной интеграции меню приложений.
- [ ] Нет встроенного updater приложения, ядра, списков и reference-пресетов.
- [ ] Нет безопасной схемы upstream sync с отчётом о локальных расхождениях.

Ориентир: loop-uh имеет updater-модуль и пользовательскую установку; Flowseal поставляет готовый bundle; bol-van содержит install scripts. Для z2guiflin нужен собственный минимальный Arch-путь без копирования Windows installer логики.

## 2. Runtime, firewall и жизненный цикл процессов

- [x] Есть plan/hash/confirmation перед изменением сети.
- [x] Owned-таблица `nftables` удаляется отдельно, без глобального reset firewall.
- [x] Номер NFQUEUE согласуется между rules и `nfqws2`.
- [x] Остановка ограничена PID, записанным самим приложением.
- [~] Есть systemd-oriented service plans, но нет завершённой установки и управления сервисом из GUI.
- [~] Launch composer умеет сочетать поддерживаемые компоненты, но не является общим supervisor.
- [ ] Нет автозапуска после входа в систему или загрузки.
- [ ] Нет постоянного health monitor с контролируемым restart/backoff.
- [ ] Нет восстановления после аварийного завершения GUI, stale rules или смены сети.
- [ ] Нет готового режима для router/LAN forwarding; текущая модель ориентирована на локального пользователя.

Ориентир: loop-uh содержит autostart, process monitoring, restart и status feedback; Flowseal предлагает service mode; bol-van содержит init/service scripts. z2guiflin пока сильнее в подтверждении и rollback, но слабее в повседневной автоматизации.

## 3. Пресеты, профили и композиция

- [x] Модель `пресет -> упорядоченные профили -> filter/range/direction/strategy` реализована.
- [x] Есть каталог, выбор, импортированные/reference и generated стратегии.
- [x] Есть визуальный конструктор базовых профилей.
- [~] Экспорт в текстовый preset существует, но не доказывает работоспособность композиции.
- [~] Есть service coverage metadata, но она не заменяет проверку фактического порядка профилей.
- [ ] Нет валидатора конфликтов между профилями: shadowing, пересечение filters, ranges и directions.
- [ ] Нет симулятора «какой профиль выберется первым» для заданного пакета/host.
- [ ] Нет безопасного merge нескольких рабочих стратегий в один preset.

- [ ] Нет live-переключения/перебора стратегий без ручного цикла.

Ориентир: loop-uh имеет развитый preset/profile UI и orchestrator; bol-van документирует строгий порядок профилей; Flowseal поставляет множество готовых вариантов. Главный долг z2guiflin — доказуемая композиция, а не количество JSON-файлов.

## 4. Blockcheck и подбор стратегий

- [x] Есть Blockcheck Lab, service target presets и bounded параметры запуска.
- [x] Успешные результаты сохраняются отдельно и могут экспортироваться.
- [x] Есть phase-aware coverage и диагностика нескольких целей сервиса.
- [x] Есть observation matrix для сравнения baseline и candidates.
- [~] Автоматизированный row runner существует, но требует owner-наблюдения и локальных прав.
- [~] Интеграция с upstream `blockcheck2` покрывает нужные сценарии не полностью.
- [ ] Нет общего live orchestrator, который безопасно перебирает стратегии на реальном трафике приложения.
- [ ] Нет автоматического повторного теста ранее рабочей стратегии после изменения сети/DPI.
- [ ] Нет статистики стабильности по времени, сети и target phase.
- [ ] Нет автоматического перехода от нескольких successful rows к проверенному preset-кандидату.

Ориентир: loop-uh заявляет live orchestrator; bol-van даёт `blockcheck2`; Flowseal делает ставку на ручной перебор готовых `.bat`. z2guiflin имеет более подробную диагностику, но ещё не сокращает путь до одной надёжной операции.

## 5. HAR и обнаружение целей

- [x] HAR workbench не привязан только к Discord и принимает HAR любого ресурса.
- [x] Есть группировка hosts по типам ошибок и кандидатам покрытия.
- [x] Есть отдельный источник Discord Voice/UDP candidates.
- [~] Workbench предлагает изменения, но не применяет их автоматически.
- [~] Связь HAR -> service target -> hostlist -> strategy существует частями.
- [ ] Нет безопасного мастера, который показывает diff и добавляет выбранные hosts в конкретную группу/hostlist.
- [ ] Нет дедупликации по wildcard/eTLD/CDN family с понятным объяснением.
- [ ] Нет сравнения двух HAR до/после стратегии.
- [ ] Нет проверки, что добавленный host действительно проходит через нужный профиль runtime.
- [ ] Нет встроенного сбора Chromium netlog/HAR с контролем приватности.

Ориентир: эта область является собственной сильной стороной z2guiflin; внешние GUI не дают готовой Linux-модели. Следующий шаг — замкнуть цикл без скрытого автоматического редактирования.

## 6. YouTube, Discord и другие сервисы

- [x] В среде владельца есть стратегии, помогающие YouTube.
- [x] В среде владельца есть стратегии, помогающие запуску и сообщениям desktop Discord.
- [x] Сервис проверяется по нескольким target phases, а не по одному домену.
- [~] Некоторые стратегии помогают сразу YouTube и Discord, но это не гарантируется.
- [~] Каталог содержит reference/candidate варианты, статус которых не всегда очевиден пользователю.
- [ ] Нет универсального пресета для YouTube + Discord + Voice.
- [ ] Нет законченных service packs для других сервисов.

Ориентир: Flowseal ориентирован на готовый массовый набор YouTube/Discord; loop-uh заявляет больше сервисов и hosts-based обход. z2guiflin должен сохранять честный статус наблюдения, а не копировать обещания универсальности.

- [~] Proxy-only путь полезен для экспериментов, но не перехватывает весь трафик приложения во всех упаковках.
- [~] Launch composer объединяет Zapret и tunnel lane только для явно поддержанных случаев.
- [ ] Нет встроенного управления subscription lists и несколькими upstream endpoints.
- [ ] Нет latency/availability выбора upstream.
- [ ] Нет TUN/TProxy реализации; существует только research plan.
- [ ] Нет WireGuard/OpenVPN управления.
- [ ] Нет policy routing по приложению, UID, cgroup или destination group.

Ориентир: v2rayNG и полноценные proxy clients имеют зрелое управление профилями и routing. z2guiflin намеренно не реализует протоколы самостоятельно, но должен лучше оркестрировать внешние cores.
