# Диагностика, ошибки и откат

Начните с Ctrl+K или `zap2-gui --find NFQUEUE`. Карточка действия показывает смысл, условия, эффект и права. Read/validate операции можно явно вызвать из palette; мутации проходят существующий plan/confirm workflow. Технические ID раскрываются отдельно, а page-local поиск пресетов остаётся самостоятельным.

| Симптом | Что посмотреть | Следующий безопасный шаг |
|---|---|---|
| Ядро отсутствует | Build dependencies и provenance | Подготовить build plan; проверить выбранный binary |
| Stale PID | Runtime status и ownership | Сверить идентичность; не убивать неизвестный процесс |
| nft conflict | Owner-rules reconciliation | Не удалять чужую таблицу; проверить owner marker |
| SOCKS работает, TLS падает | Current-run evidence по каждому mandatory target | Сопоставить TLS failure и core/server evidence, затем повторить свежую проверку |
| Discord не запускается | HTTPS, Gateway и navigation отдельно | Выполнить первый отсутствующий/упавший predicate |
| Транспорт не поддерживается | Core capability/preflight | Проверить совместимость core и connection; не менять протокол наугад |
| Обновление заблокировано | Installation receipt и conflicts | Остановить/reconcile runtime или сохранить пользовательские изменения отдельно |

Для отката firewall найдите «откат firewall», подготовьте owner-rules revert plan, подтвердите его ID и исполните штатно. Не используйте удаление всех nft tables или остановку по одному PID. Сервисный автозапуск в этом пакете **plan-only**: systemd unit не устанавливается и не включается.

Support export: `zap2-gui --support-bundle /path/new-support.zip`. В нём только положительно разрешённые identity/status/evidence fields; динамические ID и targets хешируются. Raw logs, URI, UUID/password/token/key material, HAR и configs не включаются. Поэтому это полезный краткий контекст проверки, а не полный лог или доказательство внешней доступности.

[Установка](../user/getting-started.md) · [Жизненный цикл](lifecycle.md) · [Справочник](../generated/reference.md).

P07 добавляет в support разрешённые Plan/Run summaries и typed log event projections, а также nextAction для ownership class. Все динамические ID/hash значения дополнительно хешируются; argv/message/detail не сериализуются. Полезность такого контекста при намеренно вызванной ошибке и отсутствие секретов оценивает отдельный reviewer: наличие ZIP не равно успешной оценке.

## Невыбранный VLESS и сборка ядра (v1.1)

При выборе только Zapret отсутствие VLESS profile не является ошибкой. Если start отклонён из-за whole-generation build receipt, нажмите «Собрать ядро» в Overview, проверьте зависимости/план и подтвердите. Не создавайте receipt вручную. Package build через makepkg собирает GUI-пакет, а nfqws2 staged build выполняется отдельно в конкретном workspace. После успешной сборки обновите статус; запуск станет доступен при готовности остальных inputs.

## Очистка HAR перед анализом или передачей (HAR sanitize)

Сырой HAR содержит cookie, токены авторизации, тела запросов и ответов, сообщения WebSocket и личные идентификаторы. Не передавайте его как есть. В разделе «Диагностика» (Blockcheck lab) кнопка «HAR sanitize» спрашивает исходный файл (.har, .har.gz или .zip), профиль и место сохранения, после чего записывает очищенную копию. Исходный файл не изменяется; сеть, sudo, firewall и hostlists не затрагиваются, ничего не отправляется наружу.

| Профиль | Что остаётся | Что дополнительно скрыто |
|---|---|---|
| balanced (по умолчанию) | хосты, маршруты путей, методы, статусы, версии HTTP, тайминги, размеры, коды ошибок, имена заголовков/cookie/параметров, транспортные и CDN-заголовки, адреса серверов, обобщённый User-Agent | — |
| strict | то же, кроме перечисленного справа | адреса серверов, реальное время захвата (сдвиг к 2000-01-01 с сохранением интервалов), все значения query, User-Agent, любые нестандартные сегменты путей |

Правило очистки — «запрещено всё, что не разрешено»: значение остаётся только если оно описывает сеть, а не пользователя. Секреты заменяются метками `REDACTED_<id>`, идентификаторы в путях — псевдонимами той же формы (цифра на цифру, буква на букву). Одинаковые исходные значения дают одинаковые метки внутри файла, поэтому повторное использование токена или ID остаётся видимым без раскрытия самого значения. Ключ псевдонимов случайный для каждого запуска и нигде не сохраняется.

После записи выполняется контрольный проход: результат повторно просматривается на всё, что было скрыто где-либо в файле, и на известные форматы токенов. Отчёт показывает счётчики и строку «осталось подозрительных совпадений»; при ненулевом значении файл требует ручного просмотра.

Граница: имена хостов и обычные слова в путях остаются как есть — это основная сетевая польза HAR. Имя пользователя, записанное в пути обычным словом на сайте, который очистка не знает, может сохраниться; перед публикацией просмотрите результат. Очищенную копию можно открыть кнопкой «HAR import»: хосты, статусы, коды ошибок и группы workbench совпадают с исходным HAR.

Тот же код запускается без GUI и без остальных модулей приложения: `python gui/zap2_gui/adapters/har_sanitizer.py capture.har`. Результат по умолчанию — `capture.sanitized.har` рядом с исходным; `--help` перечисляет параметры (`--profile`, `--keep-error-bodies`, `--drop-server-ips`, `--rebase-time`, `--salt`, `--out-dir`). Код возврата 0 — чисто, 2 — ошибка чтения или записи, 3 — контрольный проход нашёл остатки.

## Локальный SOCKS туннеля: пароль и случайный порт

Угроза (wiki.zapret.moe/VLESS-SOCKS5-vulnerability, 07.04.2026): локальное приложение или сайт, помогающий сканировать loopback, находит SOCKS без аутентификации на `127.0.0.1` (хорошо известные порты 10808, 1080, 9000, 16000–16100), отправляет трафик через него и узнаёт IP VPN-сервера. localhost ≠ private: привязка к loopback не защищает от других процессов той же машины.

Текущее поведение:

- inbound Xray/V2Ray генерируется с `auth: password` и случайными учётными данными (`secrets.token_urlsafe`) на каждый plan/запуск; `noauth` в конфигурации по умолчанию не появляется;
- учётные данные хранятся только в `.zap2/tunnel/runtime/<profile>.plan-socks-auth.json` и `<profile>.session-socks-auth.json` с правами 0600; в plan, отчётах, журналах и тексте GUI пароль заменён на `<redacted>`;
- порт по умолчанию (`--tunnel-socks-port 0`) — случайный свободный loopback-порт в диапазоне 20000–60999, вне сканируемых; явно заданный порт сохраняется;
- SOCKS probe выполняет RFC1929 (метод 0x02); если listener принимает NO_AUTH (0x00), это отмечается как небезопасная находка (`T0_SOCKS_INSECURE_NOAUTH`), а не как готовность;
- curl, HTTPS-проверка и env-переменные `ALL_PROXY`/`HTTPS_PROXY` получают `socks5h://user:pass@127.0.0.1:port`.

Ограничение: флаг Chromium/Electron `--proxy-server` (Discord, Vesktop) не поддерживает SOCKS-аутентификацию. В режиме с паролем такой запуск отклоняется с пояснением. Для него оставлен явный режим `--tunnel-socks-legacy-noauth` (по умолчанию выключен): plan, запуск и GUI-текст выводят предупреждение, что любой локальный процесс сможет использовать SOCKS. Используйте его только осознанно и на время эксперимента.
