# Релиз v0.4

## Решение

Состояние `v0.4-alpha_stage8f-r3` поднимается до `v0.4`.

Причина: основной продуктовый контур уже собран и проверяем. Дальнейшее удержание суффикса `alpha` создавало ложное ожидание, что релиз должен завершиться только после появления одного пресета, одинаково работающего для YouTube и Discord. Практика показала, что такое условие зависит не только от проекта.

## Что считается готовым

`v0.4` считается готовой, когда владелец может:

- запустить GUI;
- проверить ядро и зависимости;
- выбрать сервисную цель или загрузить HAR;
- получить наблюдения Blockcheck/HAR;
- выбрать существующую или экспортированную стратегию;
- просмотреть и подтвердить runtime plan;
- запустить и остановить owned `nftables`/NFQUEUE/`nfqws2` workflow;
- увидеть логи и диагностировать слой отказа;
- использовать отдельную SOCKS5/VLESS ветку без смешивания секретов и системных правил.

Все эти части присутствуют в текущем проекте.

## Что не является критерием релиза

Не требуется:

- гарантировать работу конкретной стратегии у любого провайдера;
- автоматически соединять отдельные профили в заведомо рабочий пресет;
- гарантировать одновременную работу YouTube, Discord и Discord Voice;
- считать успех одного домена доказательством работы всего приложения;
- завершать AUR-упаковку, updater, autostart или прозрачный VPN.

Эти пункты остаются отдельными задачами после v0.4.

## Новая трактовка результата

Раньше цикл был сформулирован как «починить desktop Discord». Для текущего состояния это слишком узко.

Новая формулировка:

> `v0.4` — рабочая платформа, которая помогает исследовать блокировку, собирать наблюдения, выбирать/создавать стратегии и безопасно запускать их на Arch Linux. Успех конкретной стратегии является наблюдением владельца, а не обещанием версии.

## Совместимость со старыми stage ID

Идентификаторы вида `v0.4-alpha_stage7p5` сохраняются в отчётах, схемах и исторических документах. Они нужны для совместимости старых runtime-данных и тестов. Пользовательская версия приложения и package version меняются на:

```text
PRODUCT_LABEL = v0.4
package version = 0.4.0
```

## Следующая версия

После v0.4 изменения должны группироваться по продуктовой цели, а не продолжать бесконечную последовательность `stage7...`.

Предварительные направления v0.5:

- проверяемая композиция пресетов;
- service/autostart и восстановление процессов;
- DNS/hostlist/ipset управление;
- Arch packaging;
- стабильная голосовая/UDP ветка;
- более общий routing layer для proxy/VPN.
