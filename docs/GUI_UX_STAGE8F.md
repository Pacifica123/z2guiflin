# v0.4-alpha Stage 8f — короткий запуск и мягкий GUI shell

## Цель

Stage 8f улучшает ежедневный запуск и внешний каркас приложения. Runtime,
стратегии, Blockcheck, nftables и privilege boundary не меняются.

## Запуск

Основной локальный запуск:

```bash
./run.sh
```

Если executable bit потерян после распаковки или ручного копирования:

```bash
bash run.sh
```

Launcher:

- сам переходит в корень проекта;
- предпочитает `.venv/bin/python`, затем `python3`, затем `python`;
- сам добавляет `gui/` в `PYTHONPATH`;
- без аргументов запускает GUI;
- передаёт любые CLI-аргументы в существующий `zap2_gui.app`;
- не вызывает `sudo` и не запускает сетевые действия скрыто.

Примеры:

```bash
./run.sh
./run.sh --cli
./run.sh --list-presets
./run.sh --har-workbench /path/to/site.har
```

`--cli` без дополнительных аргументов показывает обычное текстовое описание
проекта. Для всех остальных команд флаг не нужен: аргументы передаются напрямую.

## Изменения GUI

Главные разделы перенесены из верхних вкладок в постоянную левую навигацию.
Контент остаётся в `QStackedWidget`, поэтому сами страницы и их runtime-логика не
переписаны.

Добавлено:

- мягкая светлая пастельная палитра;
- единый вид карточек, кнопок, полей ввода, таблиц и scrollbars;
- понятное выделение выбранного раздела;
- короткое описание текущего раздела над страницей;
- постоянная заметка о границе plan/status и системных изменений;
- сохранение размера окна и последнего открытого раздела через `QSettings`.

## Что взято из Windows GUI

Из Windows-сборки использованы только переносимые UX-приёмы:

- вертикальная навигация из `FluentWindow`;
- карточная группировка действий;
- единый спокойный accent вместо разрозненных стилей;
- сохранение состояния окна;
- разделение обычных действий и системных изменений.

Не перенесены:

- `PyQt6-Fluent-Widgets` как новая обязательная зависимость;
- Mica/Acrylic и Windows-only backdrop;
- фоновые изображения и декоративные эффекты;
- tray lifecycle, single-instance mutex и запрос admin при старте;
- сложная система тем, анимаций и уведомлений.

Причина: эти части увеличивают поверхность ошибок и не улучшают основную цепочку
`диагностика -> стратегия -> plan -> подтверждённый запуск` на Arch Linux.

## Безопасность

`run.sh` является только локальным entry point. Он не применяет nftables, не
запускает `nfqws2`, не управляет systemd и не повышает права. Все существующие
confirmation gates остаются на месте.
