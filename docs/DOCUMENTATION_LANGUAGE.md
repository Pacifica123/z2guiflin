# Правило языка документации

## Решение

Начиная с `v0.3-alpha_stage_3`, вся активная проектная документация пишется на русском языке. Это правило введено, чтобы проект был удобен владельцу-разработчику и чтобы последующие патчи не возвращали документационную базу к смешанному англо-русскому состоянию.

## На какие файлы распространяется правило

Правило распространяется на нашу документацию:

- корневой `README.md`;
- `core/README.md`;
- `gui/README.md`;
- все файлы в `docs/`;
- служебные заметки нашего слоя внутри vendored-области, например `core/zapret2/UPSTREAM_IMPORT.md`.

## Исключения

Правило не требует переводить:

- неизменяемую upstream-документацию внутри `core/zapret2/docs/`;
- имена файлов и директорий;
- patch id, CLI-команды, API names, module names и config keys;
- названия проектов и библиотек: `zapret2`, `PyQt`, `Qt`, `systemd`, `devctl`;
- короткие технические термины, когда русский вариант ухудшает точность;
- цитаты или фрагменты reference behavior, если важно сохранить исходную формулировку.

## Правило для будущих патчей

Если будущий devctl-патч добавляет или меняет проектную документацию, текст должен быть русскоязычным. Допустимы английские идентификаторы и технические слова, но основной объясняющий текст должен оставаться на русском.

Проверки проекта должны поддерживать это решение: активные Markdown-документы должны содержать русскоязычный текст и не должны превращаться обратно в англоязычные decision records.

## Применение правила к Stage 7

Новые документы `WORKSPACE_PROFILES.md` и `STRATEGIES.md`, а также `profiles/README.md` и `strategies/README.md` считаются нашей проектной документацией и пишутся на русском языке. JSON-ключи могут оставаться англоязычными, потому что это стабильные machine-readable идентификаторы.


Stage 8 добавляет `docs/RUNTIME_LIFECYCLE.md`, `docs/RUNTIME_PLANS.md` и `runtime/README.md`; они также относятся к активной проектной документации и должны оставаться русскоязычными.
