# Язык документации

## Основное правило

Активная проектная документация z2guiflin ведётся на русском языке.

Оригинальное написание сохраняется для:

- команд и параметров CLI;
- имён файлов, классов, функций, JSON-полей и stage ID;
- `PyQt`, `nftables`, `NFQUEUE`, `systemd`, `SOCKS5`, `VLESS`, `HAR` и других технических названий;
- названий upstream-проектов и авторов;
- коротких диагностических значений, которые являются частью формата данных.

## Что не переводится локально

Документация внутри `core/zapret2/` является vendored upstream. Она хранится без локального перевода, чтобы:

- не смешивать изменения проекта с изменениями bol-van;
- сохранять возможность сверки и обновления upstream;
- не создавать ложную локальную версию официального manual.

Upstream-снимки в `meta_tools/devctl/` и внешние reference-архивы также могут сохранять исходный язык.

## Исторические документы

Stage-файлы проекта должны иметь русское описание цели, результата и текущей актуальности. Большие старые планы разрешено сокращать до русской ретроспективы, если реализация уже завершена и актуальная инструкция находится в другом документе.

## Проверка

Автотест сканирует все project-authored Markdown-файлы вне vendored upstream и требует русский текст. Команды и code blocks не считаются нарушением.
