# devctl — внешний инструмент применения патчей

devctl не входит в состав проекта. Вендоренная копия `meta_tools/devctl/` (версия 0.6.7) удалена: держать в репозитории вторую версию инструмента означало риск, что патч проверяется не тем devctl, которым он применяется.

## Требования

- Требуемая версия devctl: **не ниже 0.10.0** (`devctl --version`); пачки указывают `requiresDevctl: ">=0.10.0"`.
- devctl установлен на машине владельца и запускается из корня workspace — каталога на уровень **выше** этого проекта. Конфигурация workspace (`.devctl/workspace.json`, профили проверок) лежит там, а не в этом репозитории; её отсутствие здесь — не дефект.
- Идентификатор workspace в реестре devctl: `tgn`; проект привязан к GitHub-репозиторию `pacifica123/z2guiflin` (поле `repo` элементов пачки).
- `projectDir` — этот каталог (корень z2guiflin).

## Формат патчей и пачек

Формат описан в документации самого devctl (репозиторий devctl не публичный): файлы `docs/patch-format.md` (одиночный патч) и `docs/batch.md` (пачка патчей). Здесь они не дублируются.

## Пачки

```bash
devctl batch plan  <batch.zip>   # проверить порядок, базы и конфликты без изменений
devctl batch start <batch.zip>   # применить патчи пачки по очереди
```

- `expectedHead` указывается только у **первого** патча проекта в пачке: это фактический HEAD workspace (см. `devctl workspace list --for-agent`).
- Каждый следующий патч опирается на предыдущий через цепочку `base.after` и `expectedHead` не задаёт.

## Версия

Пачка с фичами поднимает **minor**, пачка с исправлениями — **patch**. Подъём делается одним патчем пачки во всех привязках сразу; список привязок — в [VERSIONING.md](../VERSIONING.md).

## Проверки патча

Проверки (checks) патча должны вызывать единый скрипт `bash meta_tools/run_tests.sh`. Скрипт добавляется отдельным параллельным патчем; до его появления используйте профиль из `meta_tools/README.md`.

## Доска

Каждый патч обязан обновлять `board/board.json` по правилам [board/README.md](../../board/README.md): переносить затронутые карточки и оставлять на них комментарий с patchId.
