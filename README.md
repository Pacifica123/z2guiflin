# Zap2 GUI Linux — v0.10 RC6 (P06 candidate)

Проект предоставляет графический интерфейс PyQt6, канонические ActionContract, управляемый runtime и диагностику сетевых возможностей. Он поставляет не универсальную стратегию: результат зависит от сети, ядра, целей и доказательств текущего запуска. Продукт не обещает успешную связь по одному HTTP ответу или наличию процесса.

Текущий кандидат P06: **0.10.0rc6 / v0.10 RC6**. Он не повышен до финальной версии: полный lifecycle на чистой Arch VM требует отдельного owner receipt. Последний независимо зафиксированный финальный продукт — **0.8.0**: P04 закрыт (P04a, P04b, P04c, P04d), marker `READY_FOR_USE_WITHIN_P04D`. Вход P06 — предоставленный post-P05 snapshot `ca6b4fb`; отдельная новая owner-приёмка P05 в архиве отсутствует. Это граница доказательств, а не повторное закрытие предыдущих этапов.

Начните с [установки и первого безопасного действия](docs/user/getting-started.md). [Текущая документация](docs/README.md) отделена от [истории](docs/history/README.md). [Эксплуатация и диагностика](docs/operations/troubleshooting.md), [обновление и удаление](docs/operations/lifecycle.md), [архитектура](docs/developer/architecture.md), [справочник контрактов](docs/generated/reference.md).

Поддерживаемый путь вне checkout — локальный Arch пакет из воспроизводимого source release и закреплённого PKGBUILD. Пакет владеет GUI-кодом, ресурсами и root-helper; пользователь владеет копиями ресурсов, пресетами, настройками и runtime. Service unit не устанавливается: сервисный lifecycle остаётся plan-only.

Единая детерминированная приёмка devctl и владельца: `bash meta_tools/hyperpatch_acceptance.sh --p06`. Полные логи и итоговый ZIP формируются автоматически. Чистая VM проверяется отдельным `meta_tools/p06_vm_acceptance.sh`; контейнерные проверки не объявляются её заменой. В checkout используйте `./run.sh`; для установленного продукта — `zap2-gui`.
