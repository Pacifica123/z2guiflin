# 2026-10-21-lifecycle-liveness — обновление не застревает на висящих записях runtime

Первый патч пачки B. Чинит ошибку `Zap2 install/lifecycle error: stop/reconcile owned runtime before workspace upgrade`,
которая появлялась после перезагрузки или падения: запись сессии оставалась «не остановленной», новый пакет отказывался
обновлять workspace, а открыть GUI, чтобы её снять, было уже нельзя.

## Что сделано

- `distribution.py`: вместо «любая запись не в конечном состоянии мешает» проверяется то, что можно проверить без root:
  - запись старше текущей загрузки (`btime` из `/proc/stat`) не мешает — процессы и nft-правила не переживают перезагрузку;
  - запись с PID мешает, только если процесс жив; PID, переиспользованный чужим процессом (другой cmdline), не считается;
  - `*.session-socks-auth.json` (секрет туннеля) — не запись runtime;
  - непонятные и свежие записи без PID (например, owner-rules `applied` в текущей загрузке) по-прежнему мешают: fail-closed сохранён.
- Сообщение об ошибке называет мешающие файлы и причину и подсказывает, что делать.
- Новые команды установленного пакета (работают до подготовки workspace, то есть когда GUI не открывается):
  - `zap2-gui --lifecycle-status` — какие записи держат обновление и почему;
  - `zap2-gui --lifecycle-confirm-stopped` — явное подтверждение пользователя: переносит мешающие записи в
    `~/.local/share/zap2gui/lifecycle-archive/<время>/`, ничего не удаляя; при живом процессе отказывает.
- `docs/operations/troubleshooting.md`: строка про заблокированное обновление переписана под эти команды.

## Проверки

- `tests/test_lifecycle_liveness.py`: мёртвый PID и запись прошлой загрузки не мешают; переиспользованный PID; секрет SOCKS;
  сообщение с файлами и подсказкой; перенос без удаления; отказ при живом процессе.
- `tests/test_p07_qualification.py`: «живой runtime блокирует обновление» теперь использует действительно живой PID.
- `bash meta_tools/run_tests.sh`, `check_board.py`, freeze пересчитан.
