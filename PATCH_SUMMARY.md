# 2026-10-21-presets-order-overlap — пресеты: две панели, порядок, пересечения, «кто сработает первым»

Пятый патч пачки B. Страница «Пресеты» перестроена вокруг того, как nfqws2 на самом деле выбирает профиль.

## Что сделано

- **Две панели.** Слева «Пресеты» со своими кнопками (+ Пресет, Импорт .txt, Копия для правки, Удалить пресет), справа «Профили
  выбранного пресета» (+ Профиль, Изменить, Удалить, ↑ ↓, «Кто сработает первым?»). Общие действия сверху: Применить пресет, Обновить, Сводка.
- **Клик выбирает, двойной клик включает.** Одиночный клик только открывает профили; двойной клик или «Применить пресет» делает hot-swap.
  Настройка «Применять пресет двойным кликом» (`presets/double-click-apply`; прежнее `one-click-apply` подхватывается как значение по умолчанию).
- **Список пресетов**: название жирным, под ним метки — откуда пресет (встроенный, Blockcheck, импорт .txt, strat_collection, свой, копия),
  «✓ выбран», «✖ мёртвых профилей: N» / «⚠ пересечений: N», «нет списков».
- **Порядок = приоритет.** Короткое объяснение над таблицей (полное — в подсказке), строки перетаскиваются мышью (порядок меняет файл пресета,
  таблица перечитывается), ↑ ↓ остались. Для read-only пресетов — подсказка и «Копия для правки» (`copy_preset_for_editing`: те же аргументы,
  исходник не меняется, общие списки импортированного пресета не удалятся вместе с оригиналом).
- **Пересечения профилей** (`models/profile_overlap.py`, без Qt) по правилам выбора из исходников nfqws2 (`desync.c` dp_match, `hostlist.c`,
  `ipset.c`): условия профиля через «И»; `--in-range/--out-range/--payload` не участвуют в выборе; профиль с любым hostlist, даже только
  исключающим, без имени хоста не выбирается; пустые листы = нет фильтра; `^домен` — без поддоменов.
  - ✖ «никогда не сработает» — профиль ниже целиком забирает профиль выше; строка в таблице помечена ✖.
  - ⚠ «часть трафика забирает» — с перечнем общих доменов.
  - Узкий профиль над общим — так задумано, не предупреждаем. Нечитаемый список, `--hostlist-auto`, разные fwmark — пара не оценивается.
  - Исправления в один клик для своих пресетов: «Поднять #N над #M» и «Исключить общие домены из #M» (`add_owner_profile_exclusions`
    дописывает `--hostlist-exclude-domains`, остальные аргументы профиля не трогает).
  - На встроенных пресетах анализ сразу нашёл реальные мёртвые профили: в пяти edge-flow вариантах профиль #2 отличается от #1 только
    `--out-range` и поэтому никогда не выбирается.
- **«Кто сработает первым?»** — протокол, порт, домен, IP, L7 (или «по порту»); проход сверху вниз с причиной по каждому профилю,
  победитель выделяется в таблице.
- **Редактор профиля из трёх блоков**: «1. Что ловит профиль», «2. Что пропускает (исключения)» — домены и IP/CIDR
  (`--hostlist-exclude-domains`, `--ipset-exclude-ip`), «3. Что делает (стратегия)». Исключения теперь сохраняются при правке профиля
  (раньше терялись). Перед сохранением исключения доменов в профиле без списка доменов — предупреждение о правиле имени хоста.
- В маленьком окне страница прокручивается, а не сжимает таблицу.
- Документ для пользователя `docs/user/presets.md`.
