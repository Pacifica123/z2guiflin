# 2026-10-21-self-update — обновление из GUI

Второй патч пачки B. Программа сама замечает, что есть что обновить, и обновляется по шагам так, чтобы
новый пакет не упал с lifecycle-ошибкой.

## Что сделано

- `adapters/self_update.py` (без Qt):
  - «есть обновление» = checkout отстаёт от `origin/main` (новые коммиты на GitHub) **или** состав пакета из checkout
    (releaseDigest, считается так же, как в `packaging/build_release.py`, без импорта кода из checkout) отличается
    от установленного `RELEASE_MANIFEST.json`;
  - шаги «Обновить»: остановить запущенное (через тот же stop, что у кнопки «Запуск») → `git pull --ff-only`
    (пропускается при незакоммиченных изменениях или не той ветке) → `build_local_package.sh --out ~/.cache/zap2gui/update/<версия>`
    → `makepkg -f --noconfirm` (без root) → `pkexec pacman -U` (пароль спрашивает система). Первая ошибка останавливает остальные;
    если runtime не остановился, установка не начинается.
  - Сеть трогает только `git fetch`; команды — списком аргументов, без shell.
- `widgets/update_dialog.py`: окно «Обновление» — путь к checkout (находится сам в типичных местах или выбирается),
  галочка автопроверки, «Проверить», «Обновить» с подтверждением, журнал шагов.
- `main_window.py`: кнопка «Обновление» внизу левой панели; у установленного пакета — фоновая проверка через 4 с после
  старта не чаще раза в 20 часов; при находке кнопка становится «Доступно обновление ●».

## Проверки

- `tests/test_self_update.py`: digest совпадает с `build_release.py` на реальном дереве; новые коммиты и расхождение содержимого
  на временных git-репозиториях; шаги идут в порядке stop → bash → makepkg → pkexec; при неостановленном runtime ничего не запускается;
  окно рендерится, автопроверка уважает интервал и галочку.
- `bash meta_tools/run_tests.sh`, `check_board.py`, freeze пересчитан.
